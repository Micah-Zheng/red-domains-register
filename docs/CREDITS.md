# 致谢

`tcp.red` / `udp.red` 除域名续费外几乎零成本运行，这不是因为架构精巧，
而是因为下列组织长期免费提供了本可收费的基础设施。这份清单如实记录我们依赖谁、
用到什么额度、以及**他们停止提供时会发生什么**。

写这份文档有三个用处：向提供方致谢；让用户知道服务建立在什么之上；
以及在 PSL 提交与条款说明中能指向一处清楚的依赖说明。

---

## 直接支撑本服务运行

### Cloudflare
- **提供**：权威 DNS、Universal SSL 通配证书、HTTP/HTTPS 反向代理与 CDN、
  DDoS 防护、DNSSEC、HTTP/3
- **额度**：免费版无 DNS 记录数硬上限，无查询量计费
- **不可替代之处**：Universal SSL 的通配证书是窗口期内消除 Let's Encrypt
  注册域级配额耗尽的**唯一**手段（PLAN.md D7）。没有它，本服务无法在
  PSL 收录前安全开放
- **我们的义务**：遵守免费版 CDN 条款——不得用于影音分发、网盘、大文件镜像。
  这条已写入 `TERMS.md` 并由硬规则拦截，因为**单个用户滥用会赔上整个账号，
  连带所有其他用户**

### GitHub
- **提供**：代码托管、Issue / PR 作为申请入口、Actions 计算、
  公开仓库的无限 Actions 分钟数、Dependabot、Secret scanning
- **额度**：公开仓库 Actions 免费分钟数无上限（这是 PLAN.md D3 坚持
  "主干必须公开"的直接原因）；私有侧仓走每月免费额度
- **不可替代之处**：整个 GitOps 模型——申请即 PR、审计即 Git 历史、
  执行即 Actions——都建立在这上面。同时 PR 的作者身份提供了
  免注册的身份验证（`owner.github` 须等于 PR actor）

### Let's Encrypt / ISRG
- **提供**：免费 ACME 证书签发
- **在本服务中的位置**：窗口期内被橙云覆盖而不直接使用，但**用户自行**
  为其源站签发证书时依赖它；M5 收录后灰云开放，它将回到主路径
- **我们的义务**：不把 PSL 申请当作绕过其速率限制的手段（PSL.md 已明确
  正文不以 LE 配额为论据）。速率限制是共享资源的保护机制，不是障碍

### Public Suffix List（Mozilla 与志愿维护者）
- **提供**：由**无偿志愿者**维护的公共后缀数据，被所有主流浏览器、
  操作系统与语言运行时分发
- **不可替代之处**：cookie 与 HSTS 的作用域隔离**无法用任何 DNS 手段实现**，
  只能靠 PSL 收录（PLAN.md C2）
- **我们的义务**：这是本清单里**唯一需要志愿者花时间审我们 PR** 的依赖。
  因此：提交前确保用量真实、论据充分、`make test` 通过、条目位置正确；
  不催促、不重复提交、不因被拒而反复申诉；`_psl` TXT 永久保留；
  域名期限承诺严格履行。**浪费志愿者时间的成本由整个生态承担，不只是我们**

### Resend
- **提供**：事务性邮件投递（申请结果、回收预警、`manual` 模式年度确认）
- **额度**：免费层每日与每月发信量有限，本服务的通知量应远低于上限
- **降级方案**：额度耗尽或服务变更时可切换至其他 SMTP 提供方，
  §10 的模板与 DKIM 配置是可移植的。这是本清单中**耦合最松**的一项

### Anthropic Claude
- **提供**：PR 内容分流与风险判断（PLAN.md 阶段 ②）
- **额度**：按量计费，非免费。这是本服务**唯一的非域名可变成本**
- **降级方案**：AI 层被设计为**纯降级**——它只能把申请从"自动通过"降为
  "转人工"，不能提权（PLAN.md D6）。超时、报错、额度耗尽一律 fail-closed
  转人工，因此**它下线时服务仍然完整可用**，只是审核变慢

## 上游公共基础设施

这些不由我们直接调用，但服务正确性依赖它们：

| 提供方 | 提供 |
| :--- | :--- |
| IANA / ICANN | 根区与 `.red` 的委派 |
| `.red` 注册局与注册商 | 域名注册与续费（**这是唯一的刚性付费项**） |
| Cloudflare `1.1.1.1`、Google `8.8.8.8` | 公共解析器，用于 `_psl` TXT 与可达性校验 |
| RDAP / WHOIS 服务 | 域名到期日与状态核验 |
| Node.js、Python 及其生态 | 校验、探测、下发脚本的运行时 |
| JSON Schema | 申请文件的约束表达 |

## 依赖集中度

诚实记录：**Cloudflare 与 GitHub 各自都是单点。**

| 依赖 | 失去后的后果 | 迁移难度 |
| :--- | :--- | :--- |
| Cloudflare | 全部记录与证书需迁移；窗口期内**无替代方案**能同时提供通配证书与代理 | **极高** |
| GitHub | GitOps 模型需整体重建；Git 历史可迁移，Actions 与 PR 身份验证需重写 | **高** |
| PSL | 无收录则 cookie 隔离永久缺失，服务只能限定于非敏感用途 | 不可替代 |
| Resend | 切换 SMTP 提供方 | 低 |
| Claude | 退化为全人工审核，服务仍可用 | 低 |

这种集中度是"零成本"的真实代价，不是缺陷而是取舍。记录它的意义在于：
**任一方的条款变更都可能直接终止本服务**，因此不应向用户承诺 SLA
（`TERMS.md` 已声明无 SLA），也不应让用户把关键业务架在上面。

## 回馈

免费额度不是无代价的，它由付费用户与捐赠者补贴。因此：

- **不滥用额度**：不把免费层当无限资源，不绕过速率限制，
  不用 Actions 跑无关计算
- **不转售**：本服务永久免费，不得对子域收费——拿别人补贴的资源牟利
  是对提供方最直接的背信
- **及时回收**：悬空记录既占用 CF 资源也是劫持风险，§9 的对账与回收机制
  同时服务于这两个目的
- **向 ISRG 与 PSL 相关项目捐赠**（力所能及时），并在上游发现问题时提交
  可复现的报告而非仅抱怨
- **合规优先于用户体验**：与提供方条款冲突时，站在条款一侧。
  D7 强制橙云、禁止影音分发都是这一原则的体现
