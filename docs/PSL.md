## 两个硬阻塞

### B1 · 注册期限不足

PRIVATE 段要求**提交日起算到期日超过 2 年**，且 PR 正文须包含两句明确声明：
每个提交的名字剩余期限至少 2 年、且承诺保持在良好状态并始终留有 1 年以上。
剩余期限掉到 1 年以下可能触发**自动移除**。

当前 0.47 年，不满足。今天提交需到期晚于 2028-08-25。

**处置**：各续 2 年至 `2029-02-14`。不要只续到刚好够线——提交日是滚动的，
续到"刚够今天"会在真正提交那天又不够。同时开启自动续费与注册商锁。

> **对成本模型的影响**：期限承诺把域名从"每年可放弃的支出"变成
> **不可中断的多年滚动承诺**。PLAN.md §14 需据此修订。

### B2 · 用户规模门槛

指南明确：private-use、sandbox、test、lab、beta、探索性或季节性项目**大概率被拒**；
"服务用户数不到数千的请求很可能被拒"，且不因任何人推荐而豁免。
同时必须论证"每个分发 PSL 的下游都从这次体积增长中获益"。

**处置**：接受先运营的事实。见下方「未收录窗口期」。

## 未收录窗口期的风险与缓解

这个窗口不可避免，必须诚实处理。

| 风险 | 能否缓解 |
| :--- | :--- |
| Let's Encrypt 速率限制按注册域计，全体用户共享 | **可大幅缓解** |
| Cookie / HSTS 作用域不隔离（supercookie） | **无法缓解，只能披露** |

**LE 配额的缓解**：默认 `proxied: true`。走 Cloudflare 代理时由 CF 的
Universal SSL 通配证书覆盖，**完全不触发按名字的 LE 签发**，
因此不消耗 `tcp.red` 的注册域配额。只有 DNS-only（灰云）且自行签证书的用户才会占用。

推论：窗口期内应把 DNS-only + 需要 HTTP 证书的申请**转人工并计数**，
代理模式则可自由放行。这是 §5 里 `proxied` 字段的真实用途，
不只是性能选项，而是窗口期的配额闸门。

**Cookie 隔离无法用 DNS 手段解决**，唯一诚实的做法是在 `TERMS.md` 里明写：

> 在本服务被 Public Suffix List 收录前，`*.tcp.red` / `*.udp.red` 的
> 同级子域之间**不具备 cookie 与 HSTS 隔离**。任一子域可对共享后缀写入 cookie。
> 请勿将本域名用于任何涉及登录态、支付、或其他安全敏感的用途。

窗口期内也应**刻意控制增长节奏**——这既是风险控制，也让 B2 的用量数据是真实的。

## 需要你准备的（按紧急度）

### 1. 续费（唯一紧急项，只有你能做）

各续 2 年至 `2029-02-14`，开启自动续费与 `clientTransferProhibited`。
把实际续费单价记回 PLAN.md §14。

### 2. 决定 PSL 公开署名

条目头部格式要求一行 `// Submitted by <Name> <email>`，须是你控制的、
属于该实体的地址。**这行会永久存在于每个浏览器分发的文件里**，先想清楚：

- 用个人名 还是 起一个实体名（如 `TCP/UDP Registry`）
- 用哪个邮箱 —— **建议角色地址** `psl@tcp.red`，而非个人邮箱。
  将来换人维护不必再改 PSL，而改 PSL 需要重开 PR。

### 3. 确认域名收信可用

PSL 联系、`abuse@tcp.red`、以及 PLAN.md §10 全套通知都依赖它。
需在 M0 内完成（SPF / DKIM / DMARC 见 PLAN.md §10）。

### 4. WHOIS 隐私 —— 保持开启

`_psl` TXT 是首选验证路径，**不需要** WHOIS 匹配（邮箱验证只是 fallback，
且多后缀时任一不匹配即整个 PR 被拒）。不必为 PSL 揭开隐私保护。

## 提交流程（时机成熟后执行）

### 步骤 1 · 开 PR（先不设 TXT）

`_psl` TXT 的值是 **PR 的 URL**，所以必须先有 PR 编号，顺序不能颠倒。

在 `public_suffix_list.dat` 的 `===BEGIN PRIVATE DOMAINS===` 块内，
按**注释里的公司名**字母序插入正确位置（**不是**追加到文件末尾）：

```
// TCP/UDP Registry : https://tcp.red
// Submitted by <Name> <psl@tcp.red>
tcp.red
udp.red
```

后缀排序规则：先按 TLD，再自右向左逐 label，短条目在前。

**只提交这两个裸后缀，不要用通配符。** `tcp.red` 一条即覆盖其下全部单层子域；
`*.tcp.red` 语义不同且会引来额外审查。PLAN.md §5 已限定单层，无需通配。

### 步骤 2 · 本地测试

```bash
git clone https://github.com/publicsuffix/list && cd list
# 编辑 public_suffix_list.dat
make test        # 失败的 patch 会被直接拒绝
```

### 步骤 3 · 设置 `_psl` TXT（拿到 PR 号后）

两个域名**都要设**，值均为 PR 的 URL：

```bash
# Cloudflare 面板或 API，两个 zone 各一条
_psl.tcp.red.  TXT  "https://github.com/publicsuffix/list/pull/<NNNN>"
_psl.udp.red.  TXT  "https://github.com/publicsuffix/list/pull/<NNNN>"
```

验证（须能从公共解析器解出）：

```bash
dig +short TXT _psl.tcp.red @1.1.1.1
dig +short TXT _psl.udp.red @8.8.8.8
```

> **这两条 TXT 必须永久保留。** 指南说明保留即表示"希望持续收录"，
> 未来的自动化会把记录缺失当作**移除信号**。
> 应把它们加入 PLAN.md §9.1 的 `data/infra-records.json` 白名单，
> 否则每日对账会把它们当作"非 GitOps 来源的手动记录"摘除，
> 进而在未来触发 PSL 自动移除。**这是一个真实的自伤路径。**

### 步骤 4 · PR 正文要覆盖的内容

无固定模板文件（已核实 `.github/PULL_REQUEST_TEMPLATE.md` 返回 404），
按指南要求逐项写清：

- **请求原因**：免费二级域名注册服务，用户获得自己控制的子域
- **提交数量**：2 个后缀
- **用途性质**：面向公众的通用服务，**非**内部 dev/staging
- **下游获益论证**：无收录则同级子域间 cookie/HSTS 不隔离，
  且全体用户共享注册域级 CA 速率限制 —— 收录使每个分发 PSL 的下游获得正确边界
- **示例与预期结果**：枚举 `a.tcp.red` / `b.udp.red`，说明预期
  `getPublicSuffix("a.tcp.red") == "tcp.red"`
- **规模数据**：活跃域名数、独立用户数、解析量（这是 B2 的答卷，必须真实）
- **无通配符与例外**：明确声明不涉及 `*` / `!`
- **期限声明**（两句都要）：每个名字剩余期限 ≥ 2 年；承诺保持良好状态且始终 > 1 年
- **运营证据**：服务 URL、`TERMS.md`、abuse 处理流程与响应承诺

### 步骤 5 · 等待

**无 SLA，无处理时限，无加急途径。** 合并后各下游（浏览器、OS、语言库）
自行跟随，同样无法加速。

## 会被直接拒绝的做法（自查）

| 做法 | 本项目是否触及 |
| :--- | :--- |
| 为绕过第三方速率限制（明指 Let's Encrypt）而提交 | **需谨慎措辞**：LE 配额是真实后果，但**不可将"绕过限制"作为主要动机陈述**。以 cookie/HSTS 边界为主论点，配额作为附带影响提及 |
| 第三方用户代服务方提交 | 否，你是所有者 |
| DNS 通配符式编码 IP（`1-2-3-4.foo.tld`） | 否，PLAN.md §5 禁止此形态 |
| 绕过厂商对用户的保护机制 | 否 |
| 非 ICP-3 / IETF 命名体系的 TLD | 否，`.red` 是 ICANN TLD |
| sandbox / test / beta / 探索性项目 | **是，当前即此状态** —— 这正是要先运营的原因 |
| 多后缀但邮箱不匹配全部 | 否，走 TXT 验证路径 |
