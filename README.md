# tcp.red 免费子域名

把 `你的名字.tcp.red` 指向你的站点。开源项目、个人主页、自建服务都可以申请，免费，长期有效。

申请方式是给本仓库提一个 PR：新增一个 JSON 文件。自动化会校验、贴出结论，通过后由维护者合并并自动下发 DNS。

## 申请步骤

**1. 想好前缀。** 前缀就是 `<前缀>.tcp.red` 里的那一段。规则：

- 单层小写 ASCII，4 到 63 字符，只含字母、数字、连字符，不以连字符起止
- 1 到 3 字符的短前缀全部保留，不接受申请
- 保留词（`www`、`api`、`mail` 等基础设施名与品牌名）不接受申请

**2. 新建文件** `domains/tcp.red/<你的前缀>.json`：

```json
{
  "description": "一句话说明这个域名用来做什么，附项目或个人主页链接",
  "owner": {
    "github": "你的-github-用户名",
    "contact_hash": "sha256:<见下方说明>"
  },
  "record": { "type": "CNAME", "value": "你的目标.github.io" },
  "check": { "mode": "http", "port": 443 }
}
```

四个字段都必填。`record.type` 支持 `A`、`AAAA`、`CNAME`、`SRV`。

**3. 算 contact_hash。** 我们不在公开仓库里存明文邮箱。你提交的是盐化哈希，明文只在合并后通过私有渠道收集，用于发开通通知和续期提醒。

```bash
printf '%s' "你的邮箱@example.com" | shasum -a 256
# 把输出的 64 位十六进制加上 sha256: 前缀填进去
```

**4. 完成所有权挑战。** 这一步证明你确实控制解析目标，防止有人把子域名指向不属于自己的服务器。二选一：

- **HTTP**：在目标站点放一个文件 `/.well-known/red-domains-challenge.txt`，内容是你的挑战串
- **DNS**：在目标域名上加一条 TXT 记录，内容是你的挑战串

挑战串算法（`CHALLENGE_SALT` 是公开值，见仓库 Variables）：

```bash
printf '%s' "<前缀><你的github用户名><CHALLENGE_SALT>" | shasum -a 256
```

如果目标在我们的白名单里（GitHub Pages、Vercel、Netlify 等常见托管），挑战会自动跳过。

**5. 提 PR。** 自动化会在几分钟内贴出结论评论。

## 如果校验没通过

评论里会逐条列出原因和修复方法。改完推新 commit 会自动重新校验。

挑战失败通常只是 DNS 还没传播开或文件还没生效——放好之后在 PR 里回复 `/recheck`，会重新验一次，不需要推新 commit。只有 PR 作者和维护者能触发。

## 通过之后

维护者合并后，DNS 会自动下发，通常几分钟内生效。你会收到一封开通邮件。

关于 HTTPS：`tcp.red` 的免费 Universal SSL 只覆盖一层，也就是 `你的名字.tcp.red` 有证书，但 `再加一层.你的名字.tcp.red` 没有。如果你需要更深的层级或自己签证书，在 `tls.acme_dns_delegate` 里填你的 ACME 验证域名。

## 会被拒绝的申请

钓鱼、恶意软件分发、垃圾邮件、侵权仿冒，以及解析目标明显不受申请者控制的。发现已开通的域名被滥用会直接撤销。

## 数据与注销

公开仓库里只有：前缀、GitHub 用户名、邮箱哈希、解析目标。没有明文邮箱。

想注销就提 PR 删掉自己那个 JSON 文件，DNS 记录会在下次下发时移除。需要删除邮箱明文记录的，在 issue 里说明即可——注意 Git 历史不可逆，这也是我们从一开始就不把明文写进仓库的原因。

## 本地自查

提 PR 前可以先跑一遍，和 CI 用的是同一套规则：

```bash
npm ci
npm run validate
```
